# Развёртывание Threads-бота в Amvera

Проект запускается в двух сервисах:

1. управляемый PostgreSQL в Amvera;
2. одно приложение из этого репозитория, внутри которого работают API и ровно один Telegram worker.

`app.amvera` перед каждым запуском применяет Alembic-миграции, затем запускает API и бота. Если один из процессов аварийно завершится, контейнер также завершится, и Amvera сможет его перезапустить. `docker-compose.yml` нужен только для локальной разработки.

## 1. Сохранить важные значения

До переноса сохраните в менеджере паролей:

- `TELEGRAM_BOT_TOKEN`;
- `ADMIN_TELEGRAM_IDS` — числовой Telegram ID владельца;
- `OPENROUTER_API_KEY` и точный `OPENROUTER_MODEL`;
- long-lived Threads access token отдельного пользователя;
- `TOKEN_ENCRYPTION_KEY` из текущего `.env`;
- `THREADS_CLIENT_ID` и `THREADS_CLIENT_SECRET`, если они уже используются.

Никогда не загружайте `.env` в Git или интерфейс файлов Amvera. Он исключён через `.gitignore` и `.dockerignore`.

Если переносится существующая база, `TOKEN_ENCRYPTION_KEY` должен остаться прежним: иначе сохранённый токен Threads невозможно расшифровать.

## 2. Создать PostgreSQL

1. В Amvera нажмите **Создать проект → PostgreSQL**.
2. Укажите, например, имя проекта `threads-db`, имя базы `threads_bot`, отдельного пользователя и сильный пароль.
3. Для рабочего запуска выберите тариф не ниже рекомендованного Amvera «Начальный».
4. После запуска откройте вкладку **Инфо** и скопируйте внутреннее имя для чтения/записи, оканчивающееся на `-rw`, например `amvera-username-cnpg-threads-db-rw`.
5. Внешний домен для базы не нужен.

Строка подключения приложения будет иметь вид:

```text
postgresql+asyncpg://DB_USER:URL_ENCODED_PASSWORD@amvera-username-cnpg-threads-db-rw:5432/threads_bot
```

Если пароль содержит `@`, `:`, `/`, `#`, `%` или другие специальные символы URL, закодируйте их. Получить безопасную строку можно локально:

```bash
python3 -c 'from urllib.parse import quote; print(quote(input("DB password: "), safe=""))'
```

## 3. Загрузить код

### Через GitHub

1. Создайте приватный репозиторий.
2. Закоммитьте проект и отправьте его в GitHub.
3. В Amvera создайте проект типа **Приложение** и подключите этот репозиторий.
4. Amvera автоматически найдёт `Dockerfile` и `amvera.yml` в корне.

Пример команд после подстановки адреса репозитория:

```bash
git add .
git commit -m "Prepare Amvera deployment"
git branch -M main
git remote add origin <GITHUB_REPOSITORY_URL>
git push -u origin main
```

Перед `git add` обязательно проверьте:

```bash
git status --short
git check-ignore .env
```

Вторая команда должна вывести `.env`.

### Через Git-репозиторий Amvera

Создайте приложение, выберите загрузку через Git, скопируйте показанный Amvera remote URL и отправьте текущую ветку по инструкции в интерфейсе. Не загружайте `.env`.

## 4. Добавить переменные приложения

Во вкладке **Переменные** приложения добавьте следующие значения. Токены, пароли и ключи добавляйте именно как **секреты**.

| Название | Тип | Значение |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | секрет | токен BotFather |
| `ADMIN_TELEGRAM_IDS` | переменная | один Telegram ID; несколько — через запятую |
| `DATABASE_URL` | секрет | строка `postgresql+asyncpg://...` из шага 2 |
| `OPENROUTER_API_KEY` | секрет | ключ OpenRouter |
| `OPENROUTER_MODEL` | переменная | точный slug модели |
| `OPENROUTER_TIMEOUT_SECONDS` | переменная | `30` |
| `DEFAULT_SYSTEM_PROMPT` | переменная | системный промпт |
| `THREADS_CLIENT_ID` | переменная/секрет | ID приложения Meta |
| `THREADS_CLIENT_SECRET` | секрет | секрет приложения Meta; также подписывает OAuth state |
| `THREADS_REDIRECT_URI` | переменная | временно будущий URL callback; уточняется на шаге 6 |
| `THREADS_API_VERSION` | переменная | используемая версия, сейчас `v1.0` |
| `TOKEN_ENCRYPTION_KEY` | секрет | прежний Fernet-ключ, без изменений |
| `OAUTH_STATE_TTL_SECONDS` | переменная | `600` |
| `DEFAULT_POST_INTERVAL_MINUTES` | переменная | например `60` |
| `LOG_LEVEL` | переменная | `INFO` |

`POSTGRES_PASSWORD` приложению не нужен: он уже входит в `DATABASE_URL`.

## 5. Одноразово импортировать токен отдельного Threads-пользователя

Этот шаг нужен для новой пустой базы. Если вы восстановили существующую базу с уже зашифрованным токеном, пропустите его.

Добавьте перед первым запуском:

| Название | Тип | Значение |
|---|---|---|
| `THREADS_BOOTSTRAP_TOKEN` | секрет | long-lived Threads token пользователя |
| `THREADS_BOOTSTRAP_TELEGRAM_ID` | переменная | Telegram ID владельца из `ADMIN_TELEGRAM_IDS` |
| `THREADS_BOOTSTRAP_EXPIRES_AT` | переменная | известная дата истечения в ISO 8601, например `2026-09-30T12:00:00+00:00` |
| `THREADS_BOOTSTRAP_REPLACE_EXISTING` | переменная | `true` только для одноразовой замены уже сохранённого токена |

`THREADS_BOOTSTRAP_EXPIRES_AT` можно не задавать: тогда приложение примет срок 60 дней с момента импорта. Лучше указать реальную дату выпуска/истечения токена, если она известна.

При запуске приложение:

1. проверит токен запросом к `/me` Threads API;
2. определит ID и username именно этого пользователя;
3. зашифрует токен ключом `TOKEN_ENCRYPTION_KEY`;
4. сохранит его в PostgreSQL для указанного Telegram ID.

Для плановой или аварийной ротации существующего токена задайте новый
`THREADS_BOOTSTRAP_TOKEN` и временно включите `THREADS_BOOTSTRAP_REPLACE_EXISTING=true`.
Без этого флага bootstrap безопасно пропускает уже подключённого пользователя. После строки
`Threads bootstrap replaced for @username` удалите все `THREADS_BOOTSTRAP_*` и перезапустите
приложение ещё раз.

В журнале должна появиться строка `Threads bootstrap completed for @username`. После этого удалите три переменные `THREADS_BOOTSTRAP_*` и перезапустите приложение. При случайном повторном запуске существующее подключение не перезаписывается.

## 6. Включить публичный HTTPS-адрес

1. В настройках приложения создайте бесплатный HTTPS-домен Amvera или подключите свой.
2. Проверьте:

```bash
curl -fsS https://YOUR_DOMAIN/health
curl -fsS https://YOUR_DOMAIN/ready
```

Ожидаются ответы `{"status":"ok"}` и `{"status":"ready"}`.

3. Установите переменную:

```text
THREADS_REDIRECT_URI=https://YOUR_DOMAIN/oauth/threads/callback
```

4. Если кнопка повторного OAuth-подключения нужна как резервный способ, внесите этот же URL без малейших отличий в Meta for Developers → Threads API → OAuth Redirect URLs.
5. Перезапустите приложение после изменения переменной.

При работе только с уже импортированным токеном callback не участвует в обычной публикации. Публичный API всё равно полезен для health-check и возможного восстановления подключения.

## 7. Проверить работу

1. Убедитесь, что у приложения запущена ровно **одна реплика**. Две реплики нельзя использовать: обе начнут Telegram polling и планировщик.
2. Откройте Telegram-бота и отправьте `/start`.
3. Нажмите **Статус** — Threads должен отображаться подключённым с нужным username.
4. Сгенерируйте тестовый пост через **Пост сейчас**, проверьте текст и опубликуйте вручную.
5. Убедитесь, что пост появился в профиле именно нужного Threads-пользователя.
6. Только после ручной проверки включите автопостинг.

В логах не должно быть второго сообщения о Telegram polling conflict. Если оно есть, остановите лишний локальный экземпляр бота или вторую облачную реплику.

## 8. Обновления и резервное копирование

- При каждом деплое миграции выполняются автоматически командой `alembic upgrade head`.
- Перед крупными обновлениями создавайте backup PostgreSQL средствами Amvera.
- Не меняйте `TOKEN_ENCRYPTION_KEY`.
- Long-lived токен автоматически обновляется приложением, когда до сохранённой даты истечения остаётся не более семи дней.
- После обновления проверяйте `/ready`, журнал запуска и команду **Статус** в Telegram.

## Быстрая диагностика

- **Сборка не стартует:** проверьте наличие `Dockerfile` и `amvera.yml` в корне.
- **Ошибка подключения к БД:** используйте внутренний адрес `-rw`, порт `5432`, правильное имя БД и URL-кодированный пароль.
- **`/health` работает, `/ready` нет:** API поднялся, но PostgreSQL недоступен или миграции не завершились.
- **Threads bootstrap HTTP 400/401:** токен неверный, истёк или не имеет нужных разрешений.
- **Бот отвечает только локально:** остановите локальный polling-процесс; одновременно может работать только один экземпляр.
- **Threads-токен не расшифровывается:** восстановите исходный `TOKEN_ENCRYPTION_KEY`.
